# RTL bug list

Every bug below was confirmed by running its test on the RTL with only that fix reverted (FAIL) and on the
fixed RTL (PASS).

| ID | Block | Symptom | Root cause | Fix | Test |
|---|---|---|---|---|---|
| BUG-01 | `dma_ch_link.sv` | Command link fetch stalls when a descriptor crosses a 1KB boundary (e.g. 64-bit bus, descriptor at 0x11F8 stops at 0x1200). | Beat limits (`to1k / DWB`, buffer space) were truncated to 6 bits before the comparison: 64 or 128 beats became 0, so no further AR was issued. | Limits compared at full width (11 bits). | `bugfix/dma_bug01_link_1kb_test` |
| BUG-02 | `dma_unit.sv` | `STAT_ALLCHPAUSED` / `STAT_ALLCHSTOPPED` (and their interrupt) needed two W1C writes. | The "set" statement placed after the W1C in the same `always_ff` used the old request value and overrode the clear. | Set logic evaluated before the register writes: the W1C (which also withdraws the request) wins. | `bugfix/dma_bug02_w1c_test` |
| BUG-03 | `dma_channel.sv`, `dma_ch_trig.sv` | Channel hangs in `S_TRIGOUT` if a pause hits the entry cycle of the trigger-output step. | `to_start` was a one-cycle pulse; the trigger-out FSM ignores inputs while paused, so the pulse was lost. | `to_start` is a level (`st == S_TRIGOUT`). | `bugfix/dma_bug03_pause_trigout_test` |
| BUG-04 | `dma_ch_regs.sv`, `dma_channel.sv`, `dma_ch_agen.sv` | After CLEARCMD or a Secure / Non-secure / privilege change, the INITIAL / LINEINITIAL work registers (addresses of the previous, possibly Secure, command), WRKREGPTR, STATUS / ERRINFO / interrupt flags and `ch_err` / `ch_stopped` kept old values. A STOP while done-paused / with PAUSECMD or DISABLECMD pending left the request for the next command. | `do_clear` only covered the linkable configuration registers; `donepause`, PAUSECMD and DISABLECMD were only cleared by RESUME / normal DONE. | Full clear (`clear_do | attr_chg`, not REGCLEAR) of status, ERRINFO, interrupts, work registers, generator state and status outputs; pending pause / disable / done-pause cleared when the channel goes idle. | `bugfix/dma_bug04_clear_test` |
| BUG-05 | `dma_trig_mtx.sv` | On STOP, `trig_in_ack` dropped while `trig_in_req` was still high, and `trig_out_req` was withdrawn before its ack (4-phase violation, TRM 5.4.1). | The channel clears its trigger FSMs at the stop; the matrix followed the owner's ack/req before the release arrived. | When the owner withdraws an open handshake the matrix keeps ack / req and completes the handshake itself (`ti_fin` / `to_fin`). | `ctrl/dma_trig_mtx_test` (sections 2 and 3, with a 4-phase protocol monitor) |
| BUG-06 | `dma_channel.sv` | Stream-in command hangs when the packet (single beat with TLAST) is already pending at ENABLECMD (found in the 128-bit build). | Stream flags were reset in the first XFER cycle with priority over the TLAST capture of a beat accepted in that same cycle. | Stream flags reset at command set-up (S_GPO), before the stream interfaces are active. | `directed/dma_dir_stream_test` (pending packet case) |
| BUG-07 | `dma_ch_link.sv` | 32-bit bus build failed elaboration. | Part-select `rd_lane[LB-1:2]` reversed when `LB = 2`. | Word index computed with a shift. | all tests, `d32` build |
| BUG-08 | `dma_ch_link.sv` | After a STOP (or an error) during a command link fetch, later linked commands hang or load wrong register values (status DONE without the data, "still enabled" time-outs). | The fetch abort cleared the outstanding burst / reserved word counters while link read bursts were still in flight. Their data arrived later, decremented the reservation below zero and was written into the command buffer, so the next fetch saw more free space than existed and overflowed the buffer. | Bus accounting (`outst`, `resv`) is not cleared by the abort; read data that arrives while the fetch engine is idle (aborted fetch) is dropped. Simulation assertions check reservation underflow and buffer overflow. | `bugfix/dma_bug08_link_abort_test` (found by coverage closure of the link FSM abort transitions) |
| BUG-09 | `dma_ch_trig.sv` | With software triggers in DMA driven flow control mode (`SRCTRIGINMODE/DESTRIGINMODE = 2`), one SRC/DESSWTRIGINREQ moved two blocks: a 10 element command with 4 element blocks finished after 2 requests instead of 3. | At the end of a block the request clear (`sw_req_clr`) is registered, so `CH_CMD.*SWTRIGINREQ` was still set one cycle later when the trigger FSM was back in `T_WAIT`: the same request started the next block. | The request is masked while its clear is pending (a new APB write in that cycle still wins over the clear and is seen one cycle later). | `directed/dma_dir_trig_sw_test` (found by coverage closure of the trigger FSM `T_XFER -> T_WAIT` transition) |

Earlier bugs found during bring-up (before this list was started): W data overtaking AW (BIU W order queue now
pushed at the AW handshake), FIFO output shared by the W and stream-out engines, destination lines wrapped with
YTYPE=wrap, trigger block overrun by the generator fast path, stop leaving a stream-in packet unflushed, stale
data / X on unused write strobe lanes.
